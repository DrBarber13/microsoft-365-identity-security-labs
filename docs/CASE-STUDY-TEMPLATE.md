# Case-Study Documentation Standard

This repository uses the following completed documentation standard for every identity-security case:

1. **Source and status** — distinguishes coursework-derived skills, independent extensions, and tabletop analysis.
2. **Scenario** — defines a fictional organization, assets, users, and business need.
3. **Objective** — states the security outcome and measurable success criteria.
4. **Design** — explains identity controls, dependencies, exclusions, and tradeoffs.
5. **Implementation summary** — records the administrator workflow in original language.
6. **Validation** — identifies both allowed and denied actions that demonstrate the control.
7. **Security impact** — explains which risks are reduced and which remain.
8. **Limitations** — makes licensing, telemetry, and lab constraints explicit.
9. **Lessons learned** — connects the work to analyst and administrator skills.

Public case studies never include tenant exports, access tokens, object identifiers, real domains, user information, proprietary lab instructions, or copied screenshots.
